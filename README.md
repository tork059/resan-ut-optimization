# Оптимизация рабочей базы 1С:УТ

Рабочий пульт проекта оптимизации: регламентные и фоновые задания, удаление помеченных
на удаление объектов, перевод пользователей с толстого клиента на тонкий.

**Открыть:** https://tork059.github.io/resan-ut-optimization/

Три направления разные по природе, но конкурируют за один дефицит — свободные часы суток.
Заданиям нужно машинное время, удалению помеченных объектов нужно монопольное окно,
переводу клиентов нужно окно на переключение. Поэтому всё считается от одной сетки суток.

## Устройство документа

Основной дашборд `index.html` и отдельные страницы подробных аудитов в `reports/`.
Общие стили — `dashboard.css`. Статические страницы без сборки.

| Блок | Что делает |
|------|-----------|
| Ресурсы базы | четыре шкалы дефицитов: вечернее окно, ночь, объём базы, клиентские сеансы |
| Контуры работ | три вкладки, у каждой свой инструмент и своя единица измерения |
| Очередь работ | все контуры одним списком с фильтрами + матрица эффект/усилие |
| Журнал замеров | строка на каждый замер; правка без замера не считается выполненной |
| Аудит активности пользователей | краткие выводы за 28.09–02.10.2026 и ссылка на отдельную страницу подробного отчёта |
| Сравнение терминальных серверов | краткие показатели для тех же 6 пользователей за 02.10 и 09.10.2026 и ссылка на подробное сравнение |
| Что выяснить | вопросы с указанием, какую работу каждый держит |
| Лента проекта | решения, находки и изменения документа одной хронологией |

### Контуры

- **Регламентные задания.** Единица: часы машинного времени в конкретном часе суток.
  Инструмент — карта суток. Измерено по журналу за 32 дня и выгрузке расписаний 98 заданий.
- **Помеченные на удаление.** Единица: гигабайты и часы монопольного окна.
  Данных нет, вместо них карточка замера «Объём базы и помеченные объекты» из девяти
  показателей.
- **Толстый → тонкий клиент.** Единица: секунды на открытие формы и число сеансов.
  Данных нет, карточка замера «Клиенты и сеансы». Содержит развилку: тонкий клиент
  работает только с управляемыми формами.

**Пустая шкала и прочерк означают «не измерено», а не «ноль».** Это принцип документа:
цифры не выдумываются, отсутствие данных показывается явно.

## Правка прямо на странице

В правом верхнем углу документа есть кнопка **вход**. Она открывает окно, куда вводится
персональный токен GitHub; после этого появляется режим правки — текст документа
становится редактируемым на месте, а кнопка **сохранить** коммитит изменения в этот
репозиторий. Код редактора лежит отдельно в `editor.js`: если он сломается, документ всё
равно откроется и будет читаться.

**Токен.** GitHub → Settings → Developer settings → Personal access tokens →
Fine-grained tokens → Generate new token. Repository access: *Only select repositories* →
`resan-ut-optimization`. Permissions → Repository permissions → **Contents: Read and write**.
Срок жизни — покороче. Токен хранится в localStorage этого браузера и отправляется
только на `api.github.com`; кнопка **выход** его удаляет.

**Что правится:** текст во всех разделах, а также добавление и удаление строк в очереди
работ, журнале замеров и таблице вопросов. **Что не правится:** данные карты суток
(массив `JOBS`) — одна опечатка там ломает расчёт всего табло, это безопаснее менять
в файле.

**Защита от затирания.** При входе редактор запоминает версию файла в репозитории.
Если к моменту сохранения файл изменился — например, его правил кто-то другой, — сохранение
отклоняется с просьбой перезагрузить страницу. Перезаписать чужие правки молча нельзя.

**Как вернуть всё назад.** Каждое сохранение — обычный коммит. Любая версия документа
восстанавливается из истории репозитория.

## Как править

**Карта суток считается из данных, а не рисуется.** Массив `JOBS` в конце `index.html`
задаёт для каждого задания два сценария — `now` и `aft`:

- `runs: [[стартовый час, длительность в часах], …]` — прогоны по расписанию;
- `cont: 0.204` — круглосуточное задание, часы машинного времени в каждом часе;
- `win` — то же значение внутри целевого окна, если оно другое;
- `h: {9:0.035, …}` — задание с почасовой сеткой.

Шкала вечернего окна на пульте и подписи под картой берутся из этого же массива.
Массив `RISK` — задания, которые числятся отключёнными, но могут вернуться в окно.

**Целевое окно** задаётся константами `WF` и `WT`. Поменять их — пересчитается карта,
шкала и все суммы.

**Очередь работ.** Строка таблицы `#q` помечается атрибутом `data-g` — контур и
готовность через пробел, например `data-g="jobs wait"`. Контуры: `jobs` (задания),
`vol` (объём базы), `cli` (клиенты); готовность: `go` или `wait`. По этим значениям
работают фильтры. Работа в матрице эффект/усилие размещается вручную: чип
`<span class="node c1">Короткое название</span>` кладётся в нужный квадрант
(`q1` высокий эффект/низкое усилие, `q2` высокий/высокое, `q3` низкий/низкое,
`q4` низкий/высокое). Класс `blocked` — пунктир для заблокированных.

**Без кодовых обозначений.** В документе нет номеров задач, вопросов, рисков и этапов:
на работу ссылаются коротким названием в кавычках. Если добавляете строку — давайте ей
название, по которому её можно найти, а не индекс.

**Замеры.** Новая строка в журнале замеров при каждом замере. Строки с прочерком —
запланированные, но не снятые.

## Порядок обновления

1. Внести правки в `index.html`.
2. Добавить запись в ленту проекта, если менялось содержание, а не вёрстка.
3. Поднять номер черновика в шапке и в подвале.
4. Коммит с заголовком `Пульт оптимизации vX.Y`.

Публикация — GitHub Pages из ветки `main`, корень репозитория. `.nojekyll` отключает Jekyll.
