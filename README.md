# Оптимизация рабочей базы 1С:УТ

Рабочий пульт проекта оптимизации: регламентные и фоновые задания, удаление помеченных
на удаление объектов, перевод пользователей с толстого клиента на тонкий.

**Открыть:** https://tork059.github.io/resan-ut-optimization/

Три направления разные по природе, но конкурируют за один дефицит — свободные часы суток.
Заданиям нужно машинное время, удалению помеченных объектов нужно монопольное окно,
переводу клиентов нужно окно на переключение. Поэтому всё считается от одной сетки суток.

## Устройство документа

Одна страница `index.html` без зависимостей и сборки.

| Блок | Что делает |
|------|-----------|
| Ресурсы базы | четыре шкалы дефицитов: вечернее окно, ночь, объём базы, клиентские сеансы |
| Контуры работ | три вкладки, у каждой свой инструмент и своя единица измерения |
| Очередь работ | все контуры одним списком с фильтрами + матрица эффект/усилие |
| Журнал замеров | строка на каждый замер; правка без замера не считается выполненной |
| Что выяснить | вопросы с указанием, какую работу каждый держит |
| Лента проекта | решения, находки и изменения документа одной хронологией |

### Контуры

- **К1 — регламентные задания.** Единица: часы машинного времени в конкретном часе суток.
  Инструмент — карта суток. Измерено по журналу за 32 дня и выгрузке расписаний 98 заданий.
- **К2 — помеченные на удаление.** Единица: гигабайты и часы монопольного окна.
  Данных нет, вместо них карточка замера З-2 из девяти показателей.
- **К3 — толстый → тонкий клиент.** Единица: секунды на открытие формы и число сеансов.
  Данных нет, карточка замера З-3. Содержит развилку: тонкий клиент работает только
  с управляемыми формами.

**Пустая шкала и прочерк означают «не измерено», а не «ноль».** Это принцип документа:
цифры не выдумываются, отсутствие данных показывается явно.

## Как править

**Карта суток считается из данных, а не рисуется.** Массив `JOBS` в конце `index.html`
задаёт для каждого задания два сценария — `now` и `aft`:

- `runs: [[стартовый час, длительность в часах], …]` — прогоны по расписанию;
- `cont: 0.204` — круглосуточное задание, часы машинного времени в каждом часе;
- `win` — то же значение внутри целевого окна, если оно другое;
- `h: {9:0.035, …}` — задание с почасовой сеткой.

Шкала вечернего окна на пульте и подписи под картой берутся из этого же массива.
Массив `RISK` — задания, которые числятся отключёнными, но могут вернуться в окно.

**Целевое окно** задаётся константами `WF` и `WT`. Поменять их — пересчитается карта,
шкала и все суммы.

**Очередь работ.** Строка таблицы `#q` помечается атрибутом `data-g` — контур и
готовность через пробел, например `data-g="k1 wait"`. По этим значениям работают фильтры.
Работа в матрице эффект/усилие размещается вручную: чип `<span class="node c1">К1-1</span>`
кладётся в нужный квадрант (`q1` высокий эффект/низкое усилие, `q2` высокий/высокое,
`q3` низкий/низкое, `q4` низкий/высокое). Класс `blocked` — пунктир для заблокированных.

**Замеры.** Новая строка в журнале замеров при каждом замере. Строки с прочерком —
запланированные, но не снятые.

## Порядок обновления

1. Внести правки в `index.html`.
2. Добавить запись в ленту проекта, если менялось содержание, а не вёрстка.
3. Поднять номер черновика в шапке и в подвале.
4. Коммит с заголовком `Пульт оптимизации vX.Y`.

Публикация — GitHub Pages из ветки `main`, корень репозитория. `.nojekyll` отключает Jekyll.
